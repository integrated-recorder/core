# 인증 Peer Archive API v1

상태: package-level service/client, 인증된 session 범위 요청 생성, bounded replica Lease offer/acceptance 전파, durable lease importer adapter 및 로컬 transport 시험 구현. `replica.manifest`는 `archive.view` 또는 `archive.replicate` capability 아래 공개 암호문 매핑만 반환한다. `replica.key-epochs`는 정확한 snapshot과 수신 복구 공개키 ID를 기준으로, 로컬 bundle과 현재 Owner 서명이 검증된 envelope가 모두 있는 최대 64개 epoch를 최신순으로 반환한다. 키 재료는 반환하지 않는다. `replica.offer.page`는 `archive.replicate` 권한을 확인하고 지정 provider에게만 signed offer object 목록을 최대 256개씩 반환한다. 클라이언트는 페이지 일관성과 offer hash를 확인하고, 수신측 `lease.Store.IssueOffer`가 원본 서명·현재 권한·tombstone을 다시 검증한다. `replica.acceptance`는 provider Node-Key 서명을 포함한 durable receipt만 전달하며 source `lease.Store.Accept`에서 재검증한다. `replica.verify`는 provider의 active lease와 정확한 offer hash를 확인한 뒤 source에 readback을 요청하고, source는 저장된 signed offer의 원래 source-audience capability로 provider ciphertext 전체를 bounded range로 다시 읽어 검증한다. `replica.key-envelope`는 요청된 수신 키에 묶인 Owner 서명 암호화 DEK envelope만 반환하며, 제공자와 클라이언트가 현재 identity key history에서 서명을 다시 검증한다. Control Plane peer session manager와 authenticated HTTP API는 snapshot, manifest, 로컬 recovery public key에 대한 envelope 및 제한된 ciphertext range 조회를 `archive.view` 권한으로 제공한다. Web UI는 현재 snapshot head를 표시하고, 브라우저에서 입력된 recovery phrase/file로 수신자 키를 만든 뒤 피어가 공개한 일치 epoch를 자동 탐색하고 envelope를 검증해 object별 ciphertext range를 복호화·digest 검증 후 HLS/MSE에 전달한다. 브라우저 객체 재생 상한은 평문 객체 64 MiB이며 실제 iPhone Safari/외부 네트워크 acceptance는 수행하지 않았다. Pion 통합시험은 인증된 command로 offer paging, signed acceptance 전달, signed envelope 수신 및 암호문 복제본에서 원본 bytes 복원을 연결한다. Provider는 재시작 후 필요한 immutable snapshot descriptor와 ciphertext를 peer API로 제공하며 `replica.verify` 요청 시 source-side `PeerLeaseObjectReader`가 동일 인증 session의 bounded range 명령으로 readback을 수행한다. HTTPS 전용 `POST /api/replica-imports`는 수신측에서 최신 OwnerSubject capability와 peer session을 확인하고 정확한 Offer를 명시적으로 수락한 뒤 durable importer와 source-side full readback까지 수행한다. Source의 `POST /api/replica-leases/{leaseID}/verify` 수동 endpoint도 유지된다. Global Identity UI는 수동 전달 식별자와 수신 import 폼을 제공하며 background scheduling은 없다. 이 시험의 authority verifier는 fixture이고 노드 두 개가 같은 프로세스에 있으므로 제품 coordinator/UI, 독립 노드/네트워크 acceptance, 실제 mobile playback 또는 릴리스 acceptance를 뜻하지 않는다.

기계 판독 요청 schema: [`protocol/peer-api-v1/schema.json`](../../protocol/peer-api-v1/schema.json)

## Owner tombstone 전달

`replica.tombstone`는 archive 단위 결정이므로 `snapshot_id`가 비어 있는 archive-wide `archive.replicate` peer command를 사용해 원본 `SignedTombstone`을 변경 없이 전달한다. 수신기는 archive 및 OwnerSubject scope가 command와 일치하는지 확인한 뒤 수신측 `lease.Store.AddTombstone`에 맡긴다. Store는 embedded `archive.delete` grant chain의 현재 권한, 서명 시점의 signer key, Owner 서명, 이전 tombstone head 및 fork 상태를 독립적으로 검증한다. 동일 tombstone 재전달은 idempotent이며 다른 유효 tombstone이 같은 epoch에서 경쟁하면 기존 freeze 정책이 유지된다. 검증된 tombstone 뒤 provider는 storage lock 아래 해당 Archive의 암호문 replica, key envelope, wrapped DEK, snapshot/bundle 메타데이터와 lease-scoped transfer partial을 제거한다. 다른 archive bundle이 참조하는 content-addressed ciphertext는 보존한다. 원본의 canonical recording/archive는 건드리지 않는다. provider는 정확한 tombstone hash에 묶인 Node 서명 deletion report와 erasure 요약을 반환하고, 원본은 서명과 현재 tombstone을 재검증해 durable lease 상태를 갱신한다. 이 보고는 provider의 삭제 관찰이며 저장 매체의 secure overwrite를 증명하지 않는다. HTTPS 전용 `POST /api/replica-tombstones`는 `recording.delete` 사용자 권한과 현재 archive-wide `archive.delete` + `archive.replicate` Node capability를 확인하고 저장소 잠금 아래 단일 tombstone을 서명·영속화한다. 전달 대상은 해당 Archive ID의 lease에 provider로 기록되고 현재 identity에서 여전히 위임된 Node로 한정한다. Control maintenance loop는 시작 시와 이후 1분 간격으로 미확인 전달을 재시도한다. 재시도는 같은 signed tombstone으로 erasure와 보고를 이어가며 만료·폐기·동결된 capability나 손상된 reference index는 fail-closed pending으로 남긴다.

## 전송과 권한

- 요청 command는 상호 Node-Key 인증을 마친 `ir-control-v1` 채널에서 보내며 응답은 같은 session의 bounded ordered `ir-data-v1` 채널로 돌려준다.
- command의 session ID와 target Node는 활성 인증 세션에 묶인다. 요청은 Node Key 서명, current identity projection, OwnerSubject grant, archive/snapshot/action scope, 만료, durable replay 검사를 모두 통과해야 한다.
- 서비스는 실제 archive 접근 직전에 권한을 다시 확인한다. Catalog 또는 ciphertext store의 상세 오류는 외부에 노출하지 않고 안정된 오류 코드로 축약한다.
- `snapshot.head`와 `snapshot.get`은 검증된 불변 snapshot metadata만 반환한다. 로컬 경로, 인증정보와 키는 포함되지 않는다.
- `replica.manifest`는 `archive.view` 또는 `archive.replicate` 권한으로 검증된 snapshot에 결합된 공개 coordinate-to-ciphertext 매핑을 반환한다. 평문 digest와 로컬 경로는 포함되지 않는다.
- `replica.key-epochs`는 exact snapshot의 private bundle과 요청된 recipient key ID의 현재 Owner 서명 envelope를 함께 검증해 최대 64개의 유효 epoch ID를 최신순 반환한다. 이 목록은 public metadata이며 envelope 또는 key material을 포함하지 않는다.
- `replica.key-envelope`는 snapshot, key epoch, recipient key ID에 고정된 암호화 DEK envelope만 반환한다. API는 평문 DEK나 private key를 반환하지 않는다. 제공자는 첫 grant issuer의 현재 identity key로 envelope 서명을 검증하고, 수신자는 `Client` 검증 후 자체 recovery private key로 복호화해야 한다. 서명 하나가 별도 current OwnerSubject/Capability 권한 검사를 대체하지 않는다.
- `replica.offer.page`는 persisted `StatusOffered` offer만 지정된 provider Node에 bounded page로 반환한다. 각 페이지는 같은 signed header와 전체 `OfferHash`를 반복한다. 클라이언트가 모든 object를 다시 조립한 뒤 hash를 대조하지만, 신뢰 경계는 수신 `lease.Store.IssueOffer`의 현재 authority, 역사적 서명 키, expiry 및 tombstone 재검증이다.
- `replica.acceptance`는 명령 actor와 같은 provider Node가 서명한 acceptance를 source durable Store에 전달한다. endpoint는 lease의 archive/snapshot/OwnerSubject/provider/status를 요청 scope와 대조하고, Store가 signature와 idempotent state transition을 검증한다. 응답이 유실된 뒤 lease가 `transferring` 이상으로 진행했더라도, 이미 저장된 바이트 단위 동일 영수증만 확인 응답으로 재수용한다. 만료·실패·종료 lease를 되살리지는 않는다. 응답은 lease ID/hash와 acceptance 확인 상태만 포함한다.
- `replica.verify`는 provider의 durable lease가 동일한 offer hash로 `active`인지 확인한 다음 source에 전체 ciphertext readback을 요청한다. Source는 자신이 저장한 signed offer의 source-audience grant로 각 range 요청을 다시 서명하고 provider가 범위별 현재 capability를 검증하게 한다. Source lease는 모든 선언된 길이와 SHA-256이 일치한 뒤에만 `verifying → active`로 바뀐다. 응답은 lease ID/hash/status만 전달하며 raw object, 경로 또는 키를 포함하지 않는다.
- 인증된 Control Plane HTTP route는 검증된 snapshot, 공개 replica manifest, 로컬 신원의 recovery public key로 제한된 envelope 및 크기가 제한된 ciphertext range를 제공한다. 브라우저는 커밋된 grant chain을 대체하거나 peer protocol 한도보다 큰 chunk를 요청할 수 없다.
- `ciphertext.range`는 exact snapshot, bundle, object, key epoch 및 범위가 일치하고 요청 action이 승인된 경우 암호문 바이트만 반환한다. 평문 콘텐츠 및 복호화 키를 peer에 제공하지 않는다. 수신자는 별도 durable replication lease와 object digest 검증을 적용해야 한다.

## 크기 및 프레임

- API payload의 숫자는 JSON number 대신 canonical decimal string을 사용한다. offset은 0 이상, length는 1 이상이며 최대 ciphertext chunk는 replication profile 제한을 따른다.
- 응답 본문은 최대 16 MiB다. 응답 프레임은 `IRPR` magic, 16-byte request ID, kind, 0-base chunk index, chunk count, 총 길이, 전체 본문 SHA-256 및 data를 포함한다. 각 프레임은 WebRTC data-channel 최대 크기 안에 있어야 한다.
- 클라이언트는 request ID·순서·개수·길이·SHA-256을 모두 확인한다. 동일 session의 요청/응답은 현재 직렬화한다.
- `peerapi.Client`는 고정된 archive/snapshot/OwnerSubject scope에서 매 ciphertext range마다 새 command ID·nonce를 만들고 Node Store로 서명한다. 응답 크기와 요청 길이가 정확히 일치하지 않으면 importer에 바이트를 넘기지 않는다.
- `replication.Store.ImportCiphertextObjectFromPeer`는 durable provider offset에서 시작해 최대 chunk 단위로 range를 읽고, 각 import의 fsync와 signed checkpoint가 완료된 뒤 다음 요청을 진행한다. 연결이 끊기면 다음 호출에서 durable offset 뒤부터 재개하며 이미 완료된 검증 객체는 다시 가져오지 않는다. `ImportReplicaFromPeer`는 승인된 lease에서 manifest 객체를 가져와 readback 검증 및 replica finalize까지 수행한다. Pion 통합 회귀시험은 실제 임시 Node Store 두 개로 authenticated peer API에서 offer를 페이지 전달하고 provider acceptance를 source에 전달하며, receiving `lease.Store`에서 상태 전이를 검증하고 `peerapi.Service`/`Client` DataChannel로 manifest와 range를 요청해 production importer를 완료한다. 이어 `replica.verify`를 호출해 source가 provider의 실제 durable ciphertext를 다시 읽고 source lease를 활성화하는 것도 검증한다. 수신 store를 재개방해 ciphertext와 private binding을 확인한다. 이는 fixture authority가 있는 단일 프로세스 테스트이며 독립 노드 acceptance는 아니다.
- 오류 응답은 `permission_denied`, `request_invalid`, `not_found`, `unavailable`만 허용한다. raw path, provider 오류, 키 또는 credential은 전달하지 않는다.

## 미완료 항목

실제 로컬 Pion DataChannel에서 상호 Node-Key 인증 후 snapshot, 공개 replica manifest, recipient-bound key envelope, scope-bound ciphertext range 요청/응답과 Node Store durable replay를 확인한다. 테스트는 source Node가 저장한 signed offer를 bounded page로 provider에 전달하고, provider가 이를 `IssueOffer`/`Accept`한 다음 Node-Key 서명 acceptance를 source에 전달하며, checkpoint, durable lease 상태 전이, production importer, ciphertext readback/재개방 및 envelope를 연 recovery key로 원본 bytes 복원까지 연결한다. production `peerapi.Service`, `peerapi.Client`, `lease.Store`, `replication.Store`, `nodeidentity.Store`를 사용하지만 catalog와 authority verifier는 fixture이며 두 노드는 같은 프로세스 안의 임시 저장소다. Control Plane HTTP data routes와 Web UI가 원격 object의 브라우저 복호화·HLS/MSE playback 경로로 연결됐다. 별도 회귀시험은 playlist/init-map 구성, range 분할, 암호화 객체 무결성 검증 및 loader 요청 교체 경합을 확인한다. 자동 offer 생성/배치와 background coordinator, 독립 노드의 실제 identity-history 최신성, iPhone Safari의 실제 seek/재생, 외부 네트워크 acceptance는 남아 있다.
