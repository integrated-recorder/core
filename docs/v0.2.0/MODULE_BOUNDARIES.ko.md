# v0.2 module boundaries

상태: M0 책임 경계. package 명은 구현 시 달라질 수 있지만 아래 의존 방향과 권한 경계는 유지한다.

## Ownership map

| 모듈 | 소유 책임 | 금지되는 책임 |
|---|---|---|
| `protocol/*-v1` | 버전된 wire schema, canonical bytes, limits, known-answer fixtures | storage, network, mutable application state |
| `identity` | Global Identity ID, event verification, chain head/fork/freshness state | local account login을 Global Identity로 승격, Discovery 기반 authority |
| `keyvault` | Browser recovery generation/import/export와 client-side derivation | Recovery private key를 Runtime Host/Discovery/relay로 보내기 |
| `webauthn` | HTTPS RP challenge/session ceremony, credential registration/assertion 검증 | raw WebAuthn assertion을 임의 메시지 서명으로 취급 |
| `nodeidentity` | per-installation Node Key의 보호 저장, 공개 projection, domain-separated PoP와 제한된 Lease acceptance/checkpoint 서명 | recovery key 대체, installation ID를 Global Identity ID로 대체, 임의 메시지 서명 API, 로컬 파일 상태만으로 enrollment 권한 주장 |
| `authority` | OwnerSubject, Capability issue/delegate/validate/revoke, policy epoch | route별 mutable login/role 문자열 권한 판단 |
| `discovery` | signed NodeAdvertisement lookup/publish와 signaling candidate relay | 신원 event 발급, owner/Node 권한 판정, archive key 보유 |
| `transport` | WebRTC direct, TURN allocation/fallback, bounded channel/chunk flow | authentication/authorization truth, plaintext DEK exposure |
| `archivecatalog` | stable Archive ID, immutable Snapshot descriptor 및 local archive mapping | 원본 archive root/segment을 재작성하거나 다른 canonical writer 만들기 |
| `cryptoarchive` | DEK lifecycle, per-object encryption, KeyEnvelope, hash verification | 외부 untrusted peer에게 plaintext key 제공 |
| `lease` | ReplicaLease/Tombstone 상태 전이와 signed receipt evidence | remote delete ACK를 실제 삭제 증명으로 승격 |
| `peerapi` | versioned remote request envelope, bounded parser, capability dispatch | unknown route allow, stale/forked authorization 허용 |
| `replication` | capability-checked resumable ciphertext transfer orchestration | local acquisition을 Discovery에 의존시키기, replica를 canonical recording으로 취급 |

## Existing Core ownership remains

- `internal/acquire`, `internal/archiveindex`, `internal/storage`는 기존 local canonical recording writer를 유지한다. P2P snapshot/replica는 이 경계를 대체하지 않는다.
- `internal/runtimehost/recordingowner`는 local Engine generation/worker fencing만 담당하고 Global Identity consensus가 아니다.
- `internal/authn`은 local browser account/session/RBAC 경계를 유지한다. 명시적 owner claim/migration 없이는 이를 global key ownership에 등치하지 않는다.
- `internal/storageproto`는 trusted local provider만 대상으로 한다. Network peer는 이 protocol에 직접 연결하지 않는다.

## Dependency direction

```text
protocol contracts
   ├── identity ── nodeidentity
   ├── webauthn ─────┘
   ├── authority ← identity + nodeidentity
   ├── discovery ← signed nodeidentity data
   ├── transport ← discovery signaling (untrusted)
   ├── archivecatalog ← existing archiveindex read/verified mapping
   ├── cryptoarchive ← archivecatalog + keyvault/recipient public keys
   ├── lease ← authority + archivecatalog (typed provider receipts are signed through `nodeidentity`)
   ├── peerapi ← identity + authority + bounded transport interfaces
   └── replication ← peerapi + cryptoarchive + lease + archive/storage interfaces
```

Transport and Discovery supply candidate communication only. All request validation, current authority, and object integrity remain at the peer endpoint. Local source acquisition and canonical commits have no dependency on identity, discovery, WebRTC or TURN availability.

## Current implementation boundary

The first M3 slice now exists as `internal/discoveryprotocol`, an authenticated Control Plane NodeAdvertisement signing endpoint, `internal/discovery.Directory`, and a federation client that requires two host-distinct HTTPS providers. The directory detects stale sequence replay and durably freezes same-sequence equivocation. The federation client independently verifies provider responses and excludes conflicting same-sequence candidates. Address metadata now uses a bounded RFC 9180 HPKE envelope bound to the recovery recipient, identity history head, and Node ID, with a Go/browser interoperability vector. `internal/signalingprotocol` now defines current-identity-verified signed messages, recipient/session binding, one-time X25519/HKDF session establishment, and AES-GCM encrypted SDP; `internal/nodeidentity` signs only from the active local Node key after both endpoint delegations are fresh and stores consumed signal IDs in its durable replay journal. `internal/discovery.FederationClient` publishes to at least two HTTPS providers and safely merges identical signed envelopes. `internal/peertransport.EstablishOutgoing` and `AcceptIncoming` use that broker, recheck caller-supplied node-level authorization, gather/apply encrypted SDP, and expose a bounded channel only after a mutual Node-Key transcript handshake. `internal/peerapi.SessionManager` is now connected to Control Plane through a restartable per-generation slot and authenticated/CSRF-protected session endpoints. It lazily starts only after local Global Identity and a currently delegated Node Key are available, closes all sessions before generation handoff, and re-resolves the current identity head on each handshake. Same-identity delegated Nodes are auto-connected. A cross-identity session must be explicitly initiated and is preserved only while a current, synchronized OwnerSubject capability authorizes the two Nodes; each command still rechecks its exact capability. Global Identity settings expose status plus an explicit cross-identity connect form. A Pion regression now demonstrates `snapshot.get` between two independent Global Identities when OwnerSubject A grants `archive.view` to Node B. This does not establish cross-identity Control Plane HTTP/UI coverage or replica Lease support. A local integration test uses two separate TLS Discovery directories and a Pion TURN server, asserts relay-only candidate selection, and exchanges authenticated snapshot/ciphertext messages. This remains package-level loopback acceptance: it does not prove independent provider operators, separated networks, external NAT traversal, or real installations. The remote archive UI now verifies the recovery envelope in the browser and feeds range-fetched, digest-verified plaintext objects to HLS/MSE; actual iPhone Safari and cross-network playback acceptance remain outstanding. Treat every lookup result as an untrusted candidate until the receiver validates current identity history and node authority.

M3 now also has `cmd/discovery-directory`, a single HTTPS provider executable that uses its own durable root and operator-supplied certificate. It defaults to loopback and does not provision public providers, authorize directory publishers, or supply quota/cost operations. The package can be independently deployed, but no two independent deployments have been accepted over a real network.

The M4 slice `internal/archivesnapshot` builds a content-addressed projection from a validated `archiveindex.Inventory`, separates mutable claim provenance from content identity, retains canonical discontinuity and byte-range metadata, and streams canonical object bytes through an injected reader for exact size/SHA-256 verification. New recordings persist an independent random logical Archive ID in the V2 root; RC12 roots without one retain the deterministic legacy Recording ID mapping. Root validation and writes preserve the new ID immutably. Snapshot tests show that a copy with a different local Recording ID retains the same logical archive and content snapshot identity. `acquire.Manager.BuildArchiveSnapshot` connects that projection to the real RC12 archive index and selected stored payloads; `PersistArchiveSnapshot` appends verified snapshots to `internal/archivecatalog`, which stores immutable entries and atomically advances a private head. The Recorder Engine opens this catalog under application state and, after its authenticated explicit archive-seal IPC succeeds, persists the snapshot. If the separate catalog write fails, the already-sealed canonical archive remains unchanged and repeating the seal request retries publication. A sharded archive fixture and Engine IPC regression verify exact payload digest, playback metadata preservation, sealed read projection, chain persistence, and read-only behavior. The catalog is not yet replicated by the product lease coordinator; peer playback consumes its verified snapshot through the authorized peer API and does not mutate local archive data or sign an ownership claim.

The M6 verification kernel `internal/authority` separates random person `OwnerSubject` IDs from Global Identity IDs, parses bounded signed grants, and checks a grant chain against current public identity keys, identity freshness/freeze state, a separately supplied OwnerSubject epoch, revocations, and exact archive/snapshot scope. Archive IDs enter an OwnerSubject only through a recovery-root-signed claim; grants for unclaimed IDs fail, and the locked local store rejects claims already accepted or present in authenticated fork evidence. This local uniqueness is not a cross-node ownership proof. `globalidentity.Store.AuthorityProjection` derives the local root and active Node keys from a locked validated history. `globalidentity.HistoryRegistry` stores multiple imported public histories independently from Passkey state and exposes verified current/historical projections; local identity always takes precedence in the combined resolver. Public OwnerSubject event histories now use bounded HTTPS Discovery mirrors. Before each peer command, `lease.FederatedAuthority` requires complete byte-equivalent candidate sets from every configured provider, imports every candidate through current Global Identity signature/history validation, and leaves valid successor conflicts durably frozen. Historical signed authority events are imported through a separate atomic history path; new event submissions still require the current Global Identity head. A local file import timestamp is never freshness proof. Provider agreement is an operational assumption, not cryptographic transparency, and colluding providers can replay a stale history. The browser signing helper and Go verifier share `protocol/authority-v1/test-vector.json`. Peer snapshot and ciphertext APIs recheck exact grants for every command; local canonical archive APIs are not yet subject-authorized, and RC12 archives are not migrated to OwnerSubjects. Never construct verifier context from untrusted peer fields. The Control Plane now exposes an HTTPS-only archive rekey preparation endpoint: it resolves a fresh recipient projection through the verified federation resolver, then passes that public state over authenticated Engine IPC. The Engine checks the local controller, Node delegation, committed `key.rotate` + `archive.replicate` grant chain, envelope signature/recipient binding, and re-encrypts the complete snapshot history. Historical source bytes are selected only from retained verified claims matching each snapshot digest. It returns non-secret verification commitments and a public encrypted envelope; it does not change transfer authority or establish recipient-side decryption. Browser transfer packaging, recipient verification, completion-event signing, separate-node recovery, and distributed acceptance remain incomplete.

The first M7 package, `internal/lease`, persists signed replica offers, provider acceptance and monotonic durable transfer checkpoints in one private atomic state file. It retains the latest signed checkpoint per ciphertext object, rechecks current authority at provider acceptance, and reads ciphertext back against committed size/digest before marking a lease active. Renewal has a durable owner-request/provider-receipt split so a pending operation can resume after process restart. The authenticated peer API delivers the pending owner request to the named provider, validates it in the provider Store before attaching its Node-Key receipt, and submits that exact receipt to the source; completed receipt replay is idempotent. Signed tombstones block new offers, and competing valid same-predecessor deletion events freeze rather than auto-select; an invalid predecessor is a conflict, not a fork. The HTTPS `POST /api/replica-imports` product flow performs provider acceptance, resumable ciphertext import, and source-side full readback. The Control Plane resumes only already accepted leases after restart, rechecking the OwnerSubject capability, current source Node delegation, expiry, and tombstone state. For cross-identity leases it resolves the source Node under the OwnerSubject controller identity and preserves that identity in peer session scope; lease signature keys can come from verified public identity-history registry data, while current authorization remains a separate freshness/fork check. Tombstone retry now also resolves each leased provider Node to a unique, fresh identity before connecting and delivering; stale, revoked, or ambiguous identity mappings remain pending. These paths have targeted Control Plane regression coverage. The signed per-OwnerSubject retention target (minimum replicas, grace period, capacity cap, and relocation preference) is now applied by a bounded maintenance scheduler. It considers sealed snapshots only when the source encryption key and Owner recovery envelope are already prepared, rechecks fresh identity history and current `archive.replicate` grants for both the source and each candidate provider, enforces subject capacity and relocation grace, and creates at most two Offers per pass. A connected peer is only a transport candidate; it is not authorized without the provider-scoped grant. Offers are never auto-accepted and transfer does not start automatically. Initial key/envelope preparation, acceptance/transfer orchestration, and independent two-node/network acceptance remain incomplete. A signed peer deletion report is not proof that physical files were erased; this is not M7 acceptance.

The M5 integration slice `internal/replication` consumes an already verified immutable `archivesnapshot.Snapshot` and a read-only canonical source. `acquire.Manager.SnapshotObjectSource` binds the source to a current sealed RC12 inventory. Encryption rechecks each original object against the snapshot, stores encrypted payload objects under a private local store, and keeps source coordinates/plaintext hashes in a private binding manifest. The source Engine also stores each DEK in an immutable local slot wrapped with a domain-separated key derived inside the protected Node Key store; plaintext DEKs are never written to disk or returned to peers. `CiphertextRefs` is the minimal lease object set; a separate explicit `ReplicaManifest` maps public snapshot coordinates to ciphertext IDs/digests without repeating plaintext hashes, local paths, or keys. Its canonical hash must be bound by the source Node-signed lease offer. JSON serialization of private `Bundle` and `ObjectBinding` is rejected. Replication requires a current `archive.replicate` grant before source reads and again before manifest publication. Peer ciphertext reads require a fresh exact-snapshot `archive.view`, `archive.export`, or `archive.replicate` grant and verify the stored ciphertext digest; bounded range reads expose only ciphertext and rely on receiver-side whole-object digest validation. The authenticated peer API and Control Plane routes now expose verified snapshots, public manifests, local-recipient encrypted DEK envelopes, and bounded ciphertext ranges. Inbound chunk import requires a matching durable local lease, rechecks tombstone/expiry/provider/object-set state, fsyncs each prefix before the local Node Key signs its offset, truncates uncheckpointed crash tails, and rejects stale concurrent offsets. Finalization reads every ciphertext back through the lease state machine before persisting the private mapping. Local restore decrypts all objects to a private sibling staging directory and atomically publishes only a complete byte-verified raw-object tree. This does not yet provide a complete product offer/accept coordinator or independently operated two-node acceptance. The browser now decrypts authorized peer objects in memory and supplies them to an HLS/MSE player, with a 64 MiB per-object playback ceiling; mobile Safari and cross-network playback have not been tested. RC12 archive reconstruction into the existing app VOD path and end-to-end DEK lifecycle remain incomplete; this is not M5/M7 acceptance.

## Test harness boundary

### 2026-11-26 local WIP hardening

The Control Plane tombstone reconciler now stores a bounded delivery cursor in the existing private lease state. Lease state v1 is strict-decoded and validated before an atomic v2 rewrite; malformed v2 state still fails closed. The planned end-of-batch cursor is persisted once before peer calls, so restart after an incomplete pass continues beyond the prior batch and wraps over still-unacknowledged deliveries. This cursor is scheduling metadata only: it never records deletion success, changes tombstone authority, or replaces an authenticated receipt. The wire protocol is unchanged. Local tests cover populated v1 migration, malformed cursor rejection, store reopen, and bounded retry selection; this does not prove remote provider deletion or distributed tombstone convergence.

Remote browser playback now binds its decryption session to the selected `(identity_id, node_id)` peer pair and the exact archive grant. Capability removal/expiry, authorization lookup failure, or a changed peer session stops playback, revokes the object URL, and zeroes the in-memory DEK. A periodic local API refresh drives this cleanup; it does not revoke plaintext already observed or recorded by a user and does not replace per-request backend authorization.

M0's Go/Node harness exercises shared identity/recovery vectors and the “two valid successors freeze” rule in memory. M2 additionally tests durable fork evidence, Node Key delegation/revocation validation, protected per-installation Node Key storage, the public multi-identity registry's invalid-signature rejection, anti-rollback, persistent fork freeze, and UI import of public history. The UI can display and scan a bounded one-use enrollment proof QR, with strict parsing and the existing Owner-root signature path; JSON transfer remains available. Component and UI integration tests are local browser tests, not physical inter-node enrollment acceptance. M2 still needs authenticated replicated history, two independent nodes, and reboot/fork acceptance on independent systems. None of this satisfies M3's distinct-network ICE/TURN or M4–M8's archive replication/playback exit criteria.
