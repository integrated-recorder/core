# Integrated Recorder v0.2.0 구현 상태

요구사항별 실제 구현 위치, 실행된 검증, 미해결 조건은 [Requirement-to-Evidence Matrix](REQUIREMENT_EVIDENCE.ko.md)에 추적한다. 마일스톤 표의 상태는 해당 acceptance gate가 모두 완료됐다는 뜻이 아니다.

기준 소스는 `v0.1.0-rc.12`의 commit `d4a14d4fab908a0cb415dacd47e7f0d9bc63be8d`입니다. 이 문서는 구현 완료를 선언하지 않고, 단계별 증거와 미완료 gate를 기록합니다.

| M5 | 콘텐츠 암호화·키 패키징 | 진행 중 | `internal/cryptoarchive`와 browser crypto module에 bounded AES-256-GCM object format, HPKE recovery DEK envelope, Go↔browser object/envelope 시험 벡터가 있다. `acquire.Manager.SnapshotObjectSource`는 현재 RC12 inventory에 다시 대조한 sealed snapshot만 read-only canonical source에 연결한다. `internal/replication`은 source bytes를 재검증해 ciphertext object로 저장하고 private local binding과 public coordinate→ciphertext manifest를 분리한다. public manifest hash는 signed Lease Offer가 고정하며 ciphertext 수신은 해당 provider의 durable transferring lease가 허용한 exact object만 받는다. provider-side chunk import는 fsync 이후 Node Key checkpoint를 저장하고 재시작 시 durable offset부터 재개하며 완료 후 full ciphertext readback을 수행한다. peer API는 bounded range를 scope-bound Node-Key command로 요청하고 현재 신원 key history에 맞춰 Owner 서명 envelope를 검증한다. authenticated Control Plane HTTP routes는 capability 재검증 후 manifest, 로컬 recovery public key용 envelope, 제한된 ciphertext ranges를 노출한다. HTTPS secure context 및 Media Source Extensions가 필요하고 평문 객체당 64 MiB 상한이 있다. 실제 iPhone Safari 재생/seek와 서로 다른 네트워크 인수시험은 미실시다. sealed RC12 archive → Snapshot → ciphertext → 복구 envelope → 원본 바이트/HLS 복원 수직 회귀시험이 추가됐다. 이는 Core RC12 archive로의 import나 모바일 playback가 아니다. 독립 두 노드 acceptance 및 보안 검토 전. |
| M6 | OwnerSubject·Capability | 진행 중 | `internal/authority`에 person OwnerSubject ID 분리, Global Identity 저장소의 역사 시점 root/Node Key projection, bounded signed grant parser, current-key chain 검증, archive/snapshot scope·action·TTL·위임 depth 제한, 5분 freshness 상한, revoke·transfer 검증 및 epoch bump/rekey-required 결과가 추가됨. transfer event에서 기존 claim Archive별 재키잉 대기를 재구성하고, 해당 archive의 새 grant 발급과 인가를 재키잉 완료 전까지 fail-closed로 거부하는 테스트가 추가됨. 별도 신규 Archive claim은 영향받지 않는다. 새 보호 파일에 signed authority event를 append하고 경쟁 유효 이력을 동결하는 durable store, 재시작 복구, 한 저장소 안에 중복을 막는 signed Archive claim, 미claim archive grant 거부, scope가 제한된 claim/grant 발급·폐기 UI에 `key.rotate` capability 선택을 포함하고 system RBAC/CSRF로 보호되는 조회·fork-evidence 이력·이벤트 API가 추가됨. 브라우저 recovery key는 signing 동안에만 메모리에 있고 server request에는 서명 산출물만 포함된다. Discovery는 서명 OwnerSubject history를 opaque bounded mirror로 보관하고, Control Plane은 mutation 결과를 모든 mirror에 게시하며 각 원격 peer command 직전에 provider 전체의 후보 집합이 일치하는지 재조회한다. Recorder는 각 후보의 서명·과거 identity head를 자체 검증해 durable store로 병합하고, 두 유효 successor가 있으면 자동 선택 없이 동결한다. 중단된 게시를 재시도할 때 기존 로컬 head를 먼저 동기화해 이전 head의 새 mutation이 조용히 덮어쓰이지 않도록 한다. provider 집합은 운영상 freshness quorum이며, 두 provider의 공모된 stale replay를 막는 암호학적 최신성 증명은 아니다. 동일 Global Identity 안의 history exchange 통합 테스트 및 historical head import 검증이 추가됐다. Capability는 peer API 명령과 명시적 replica import HTTP 경로에서 다시 검증된다. Control Plane은 위임된 source Node 세션을 자동 관리하고, 수신 화면은 현재 OwnerSubject가 claim한 archive 범위에서 source Node의 제한된 pending Offer metadata를 찾아 사용자가 선택하게 한다. 원본 서명 Offer는 기존 수신 검증 경계를 통과하고 수락·전송은 명시적으로 시작한다. 보호된 Engine IPC와 HTTPS API를 통한 이전 DEK 검증·전체 snapshot history 재암호화·수신자 envelope 준비에 더해, 브라우저에서 만료·현재 identity head·공개키 바인딩 및 양측 서명을 확인하는 파일 기반 이중 동의 offer/accept/application 경로가 추가됨. 이전 이벤트 적용 뒤 기존 claim archive는 재키잉 검증 전까지 잠기며, browser UI가 source 재키잉 준비, recipient envelope 열기·전체 history/새 ciphertext 검증, evidence 파일 생성, 새 controller의 pending Archive 전체 완료 서명을 연결한다. 검증은 신뢰하는 client에서 수행되며 server가 recipient 복호화를 독립 증명하지 않는다. 자동 복제 coordinator 및 실제 두 노드/네트워크 acceptance도 미완료. |
| M7 | 복제 Lease·Tombstone | 진행 중 | `internal/lease`에 durable offer/accept/checkpoint/readback/expiry/tombstone/fork-freeze state machine과 current authority-log chain 검사 기반이 추가됨. 객체별 최신 서명 checkpoint만 보존해 청크 수에 따른 상태 무한 증가를 막고, acceptance 시 현재 권한을 재검증한다. renewal은 owner 승인 요청을 저장한 뒤 provider receipt를 별도 완료해 중간 재시작 후 재개한다. 잘못된 predecessor는 fork로 동결하지 않는다. provider deletion report는 실제 provider-side encrypted replica cleanup 이후 반환되는 관찰 결과이며 secure overwrite의 암호학적 증명으로 취급하지 않는다. Control Plane은 설치 준비 시 만료 상태를 즉시 조정하고 이후 1분 간격으로 확인하며 세대 handoff 중 중지·재개한다. 인증된 peer command로 지정 provider에게 offer를 최대 256 object씩 전송하고, 수신 Store의 원본 서명·최신 권한 검증 후 provider 서명 acceptance를 source Store에 전달한다. acceptance 이후 양쪽 lease의 `Transferring` 전이를 연결하며, provider가 각 객체의 fsync 이후 Node-Key로 서명한 checkpoint를 source에 즉시 전달한다. source 응답 유실 뒤 재시도는 동일 checkpoint만 idempotent하게 재생하고, verifying/active 상태에서 새 offset을 받아들이지 않는다. 갱신 요청과 provider 서명 receipt도 같은 peer command 경계에서 전달하며, 완료 응답이 유실된 뒤 정확한 같은 receipt를 재전송해도 상태가 중복 전이되지 않는 Pion 회귀시험이 추가됐다. Control Plane은 만료 24시간 이내인 `owner_approval` lease만 현재 OwnerSubject 정책·Capability·Node 위임을 다시 확인해 자동 갱신 요청으로 시작하고, provider가 동일한 peer 경계에서 Node-Key receipt를 완료한다. `manual` lease, 만료 lease, tombstone 대상은 자동 갱신하지 않는다. Provider는 source의 확인 응답을 받기 전까지 `renewing` 요청을 durable 상태로 유지한다. 요청 수신·receipt 서명·source 응답 뒤 재시작하면 같은 결정적 Node-Key receipt를 다시 서명·전달해 source 확인 후 상태를 완료한다. HTTPS 전용 `POST /api/recordings/{id}/replicas/offers`는 검증된 sealed snapshot을 암호화한 뒤 매니페스트와 `key_epoch`에 결합된 Node 서명 Offer를 저장하며, UI는 위임 provider 선택과 재시도 가능한 lease ID를 제공한다. 보호된 Lease store 및 `GET /api/replica-leases`의 서명·grant chain 제외 상태 요약도 Control Plane에 연결됐다. 수신측은 HTTPS 전용 `GET /api/peer-archives/{nodeID}/replica-offers`로 현재 OwnerSubject가 claim한 archive와 local Node의 유효한 `archive.replicate` Capability에 한정된 pending Offer 요약을 가져올 수 있고, UI는 이를 명시적으로 선택해 기존 수신 검증·수락 흐름에 전달한다. 응답은 서명, grant chain, ciphertext object ID와 키 재료를 제외하며 선택 후에도 원본 signed Offer 전체를 peer API에서 재검증한다. HTTPS 전용 `POST /api/replica-imports`는 수신측에서 정확한 source, OwnerSubject, capability, archive, snapshot, lease를 다시 검증하고 명시적 수락·재개 가능한 ciphertext import·source readback을 한 요청 흐름으로 수행한다. HTTPS 전용 `POST /api/replica-tombstones`는 OwnerSubject의 archive-wide `archive.delete` + `archive.replicate` capability를 재검증하고 lease 저장소 잠금 안에서 단일 signed tombstone을 원자적으로 생성한다. 현재 위임 상태와 archive lease provider를 대조해 필요한 Node에만 전달하고, cross-identity provider는 verified registry와 매 pass 최신 identity resolution에서 유일하게 확인될 때만 연결하며 stale·revoked·ambiguous target은 pending으로 둔다. 검증된 receipt를 durable state에 기록한다. 현재 M0–M7은 구현 중이다. M8에는 제품 API와 UI를 연결한 Chromium encrypted playback E2E가 있으며 합성 fMP4 fixture의 암호문 다운로드·복호화·재생·seek를 확인한다. 다만 peer는 in-process fixture이므로 별도 Recorder 간 네트워크 경로와 mobile Safari acceptance는 미완료이며 M9도 미완료다. M3 peer-session lifecycle/API와 설정의 자동 세션 상태 표시가 연결됐고, Control Plane이 현재 history의 다른 위임 Node 세션을 자동 재조정합니다. 같은 신원 Node는 자동 연결되며, 다른 신원은 현재 서명 권한을 확인해 명시적으로 연결할 수 있습니다. 조정기는 다른 신원 세션을 권한이 유효한 동안만 유지하고 폐기·만료 후 닫습니다. 연결 자체는 명령 권한을 부여하지 않으며, archive API/복제 흐름의 교차 신원 완결성과 독립 노드·네트워크 인수시험은 미완료입니다. Docker daemon이 없는 개발 환경에서 분리 컨테이너 네트워크·독립 운영자·공용 외부망 acceptance를 수행하지 않았습니다. M4는 실제 sharded archive fixture에서 canonical inventory/payload를 검증하고, Engine seal IPC 후 immutable snapshot catalog에 기록합니다. Snapshot v2는 init-map cross-reference를 포함합니다. M5는 sealed RC12 payload에서 recovery envelope까지 이어지는 통합 시험과 별도 private tree의 HLS 복원 검증, authenticated peer/HTTP ciphertext retrieval을 포함하지만, 결과물을 Core RC12 archive로 import하지 않으며 Web UI에서 secure context와 MSE를 통한 원격 encrypted HLS playback slice가 동작하지만 iPhone Safari와 외부 network acceptance는 미실시입니다. 수신 노드는 이제 OwnerSubject ID를 지정해 설정된 모든 Discovery mirror에서 공개 서명 권한 이력을 명시적으로 동기화할 수 있습니다. mirror 응답이 일치하고 서명된 이력이 현재 Global Identity 검증을 통과할 때만 적용되며 동작은 로컬 관리 권한과 CSRF로 보호되고 감사 로그에 기록됩니다. Global Identity 설정 UI는 봉인 Archive 재키잉 준비 파일을 교환하고, 수신자가 새 recovery envelope를 열어 각 immutable snapshot history와 새 epoch ciphertext를 브라우저에서 검증하고, 그 증거를 파일로 보관한 뒤 새 controller가 pending Archive 전체에 대한 완료 이벤트를 서명하도록 연결합니다. 서버는 브라우저 복호화를 재검증하지 않으며 이 서명은 recipient의 완료 선언입니다. 서로 다른 운영자·노드에서의 transfer acceptance와 공격적 분산 검증은 미완료입니다.

- Pion 직접 연결 fixture는 TURN을 구성하지 않은 두 로컬 peer 사이에서 선택된 ICE 경로가 UDP이며 relay candidate를 사용하지 않는지 확인하고, 인증된 DataChannel 교환도 검증한다. 후보는 환경에 따라 host 또는 peer-reflexive일 수 있다. `go test -race -count=20 -run '^TestLocalPeerConnectionUsesBoundedOrderedDataChannel$' ./internal/peertransport`로 반복 검증한다. 같은 호스트 ICE 시험이지 NAT 통과나 외부 네트워크 direct-path acceptance가 아니다.
- 별도 회귀시험은 두 OS 프로세스가 서로 다른 durable Node Key 저장소를 열고, 별도 TLS Discovery endpoint/store를 통해 암호화 signaling과 상호 Node-Key 인증을 마친 뒤 bounded DataChannel을 교환하며 oversized frame을 거부하고 재시작 후 같은 Node ID로 재연결하는 것을 확인한다. 일반 20회, race 10회 반복 통과. 동일 호스트와 fixture identity resolver를 사용하며 Control Plane 권한·폐기, 독립 운영자, 외부망/NAT 또는 운영 TURN을 검증하지 않는다.
